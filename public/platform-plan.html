Hook System for Extensibility

// Hook System - allows modules to extend each other class HookSystem { private hooks: Map<string, HookHandler[]> = new Map(); // Register a hook handler register(hookName: string, handler: HookHandler, priority = 10): void { const handlers = this.hooks.get(hookName) || []; handlers.push({ handler, priority }); handlers.sort((a, b) => a.priority - b.priority); this.hooks.set(hookName, handlers); } // Execute filter hook (modify data) async applyFilters<T>(hookName: string, value: T, context: HookContext): Promise<T> { const handlers = this.hooks.get(hookName) || []; let result = value; for (const { handler } of handlers) { result = await handler(result, context); } return result; } // Execute action hook (trigger side effects) async doAction(hookName: string, context: HookContext): Promise<void> { const handlers = this.hooks.get(hookName) || []; await Promise.all(handlers.map(({ handler }) => handler(context))); } } // Example: Booking module adds customer data hooks hookSystem.register('customer.display', async (customer, ctx) => { // Add booking history to customer display const bookings = await getCustomerBookings(customer.id); return { ...customer, bookingCount: bookings.length, totalSpent: bookings.reduce((sum, b) => sum + b.total, 0), lastBooking: bookings[0]?.date, }; }); // Example: Marketing module adds to booking form hookSystem.register('booking.form.fields', async (fields, ctx) => { return [ ...fields, { name: 'referralCode', type: 'text', label: 'Referral Code', validation: { optional: true }, }, ]; });

Database Architecture & Multi-Tenancy

Multi-Tenancy Strategy

The platform uses a Shared Database, Shared Schema with Row-Level Security (RLS) approach for optimal balance between isolation and resource efficiency.

🏢

Tenant Isolation

Every table includes a tenant_id column with PostgreSQL RLS policies ensuring complete data isolation.

📊

Schema-per-Module

Each module's tables are prefixed (e.g., crm_customers, inv_items) for organization.

🔒

RLS Policies

Automatic tenant filtering at database level prevents cross-tenant data access even with bugs.

⚡

Performance

Composite indexes on (tenant_id, id) and partitioning for large tables ensure scalability.
