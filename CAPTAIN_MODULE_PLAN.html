Key Implementation Notes

  • Mobile-First Design: All captain UI must be designed mobile-first as captains primarily use phones on boats
  • Offline Capability: Critical for boat tours where cellular signal may be unavailable - implement IndexedDB + Service Worker
  • Large Touch Targets: All interactive elements should be at least 44x44px for easy tapping on moving boats
  • Battery Efficiency: Minimize background processes to preserve battery life during long tours
  • Quick Actions: Check-in should be achievable in 2 taps maximum
  • Data Sync: Implement optimistic UI updates with background sync and conflict resolution
  • Push Notifications: Use Firebase Cloud Messaging for cross-platform push support
  • Security: All captain APIs must verify availability_staff assignment before allowing access
  • RLS Policies: Implement row-level security to ensure captains only see their assigned data
